# Security Policy

## Supported versions

Security support begins with the first published release. Before that release,
accepted security fixes target the default branch. After releases begin, the
supported version range will be maintained in this document.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a public issue, discussion, pull
request, or social channel.

Use GitHub's
[private vulnerability reporting](https://github.com/mevlutkural/moduleos/security/advisories/new)
for this repository. Include, when possible:

- the affected component and version or commit;
- a clear description of the impact;
- reproduction steps or a minimal proof of concept;
- required privileges and environmental assumptions;
- suggested mitigations, if known.

You should receive an acknowledgement within seven days. Validation, remediation,
and disclosure timing depend on severity and complexity. Please allow a
reasonable remediation window before public disclosure.

## Scope and expectations

Good-faith research that avoids privacy violations, data loss, service
disruption, and access beyond what is necessary to demonstrate the issue is
welcome. This project does not currently operate a paid bug bounty program.

Security fixes may be developed privately and released with limited detail until
users have had a reasonable opportunity to update.
